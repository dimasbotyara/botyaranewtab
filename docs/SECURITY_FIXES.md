# Исправления безопасности и надёжности

Набор защитных правок по итогам код-ревью. Ни одна фича и ни одна настройка
не изменились по смыслу — только валидация, экранирование и обработка ошибок.

Проверка: `pip install -r requirements-dev.txt && pytest` — 53 теста, ~1 секунда.

---

## 1. Восстановление бэкапа больше не может уничтожить данные

**Было:** `restore_backup()` сначала удалял текущую базу (вместе с `-wal`/`-shm`),
затем копировал присланный файл. Любой мусорный файл → база уничтожена, приложение
отвечает 500 на всё, откатить нечем.

**Стало** (`utils.py`, `app.py`):
- `is_valid_backup()` — файл проверяется до любых изменений: размер, набор таблиц
  (`settings`, `shortcuts`), `PRAGMA integrity_check`; подключение read-only + immutable;
- текущая база **перемещается** в `backups/pre_restore_*.db`, а не удаляется;
- при любой ошибке копирования файлы возвращаются на место (rollback);
- невалидный файл → `400` и база не тронута;
- временный файл восстановления уникален (`restore_<uuid>.db`) и удаляется в `finally`;
- `create_backup()` больше не перезаписывает бэкап, сделанный в ту же секунду.

## 2. Stored XSS закрыт

**Было:** заголовки шорткатов, названия групп, каунтдауны, мировые часы, история
поиска и имена файлов вставлялись в `innerHTML` без экранирования. Вектор
реальный: импорт HTML-файла закладок браузера подхватывает `<title>` страницы.

**Стало:** новый `static/js/utils.js` с `esc()`, `safeColor()`, `safeUrl()`;
все точки подстановки пользовательских данных переведены на них
(`shortcuts.js`, `settings.js`, `widgets.js`, `search.js`). Цвета принимаются только
в виде `#rgb/#rrggbb/#rrggbbaa`, иконки — только относительные пути внутри `/static`.

## 3. URL шорткатов валидируются и на PUT

**Было:** `POST` требовал `http(s)`, `PUT` — нет: `javascript:alert(1)` сохранялся и
попадал в `href`.

**Стало:** единый `clean_shortcut_fields()` для создания и обновления. `clean_url()`
блокирует не-http(s) схемы, кавычки/пробелы/управляющие символы, нечисловые порты
(`https://x:alert(1)`), проверяет hostname через IDNA (кириллические домены работают).
Неизвестный `id` → `404` вместо `200 {}`.

## 4. Сервер больше не вешается одним запросом

**Было:** калькулятор использовал `eval()` с санитайзером, который не ограничивал
стоимость вычисления: `9**9**9**9` занимал поток навсегда, а `/api/search/parse`
вызывается на каждый ввод с debounce 150 мс; waitress с `threads=4` → полный отказ.

**Стало** (`search_engine.py`): обход AST вместо `eval`, лимиты на длину выражения (100),
глубину (20), показатель степени (64) и величину результата (1e18); поддерживаются
`sqrt/log/sin/...`, `pi`, `e` — раньше они вырезались санитайзером и не работали.

## 5. Запись в API с чужого сайта заблокирована

**Было:** `get_json(force=True)` игнорировал `Content-Type`, поэтому любая открытая
вкладка могла отправить `text/plain` POST на `127.0.0.1:12121` и молча поменять настройки.

**Стало** (`app.py`):
- `before_request`-защита для небезопасных `/api/*`: `Sec-Fetch-Site: cross-site` → `403`,
  чужой `Origin` → `403`, Host не локальный/не приватный → `403` (закрывает DNS-rebinding);
- `get_json(silent=True)` + требование объекта JSON → `400`;
- добавлены `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`, `Cache-Control: no-store` для API.

Локальная работа не меняется: `localhost`, `127.0.0.1`, `::1`, приватные IP и имена
вида `machine`, `*.lan`, `*.local` проходят. Своё имя — через `BOTYARA_ALLOWED_HOSTS`
(см. README), `*` отключает проверку имени хоста (нужно за обратным прокси).

## 6. Поиск: кодирование запроса и порядок проверок

- `cat & dog` больше не обрезается до `cat`, `100% скидка` не ломает URL — всё через `quote_plus`.
- `1.5` больше не считается доменом: калькулятор проверяется до `is_url`, а TLD
  обязан содержать буквы. `http://`, `192.168.1.1`, `localhost:12121` распознаются как URL.
- То же исправление продублировано в `search.js` (кнопка «добавить в шорткаты»).
- `geocode_city` кодирует название города.

## 7. 400 вместо 500 и JSON-ошибки

- `?hour=abc`, `?limit=zzz` → `400` (было `500`), значения зажимаются в допустимый диапазон;
- `POST /api/countdowns` и `/api/world-clocks` без обязательных полей → `400` с текстом
  (было `KeyError` → `500`); таймзона проверяется через `zoneinfo`;
- любой `/api/*` отвечает JSON'ом на 404/405/500, а не HTML-страницей Flask.

## 8. SSRF в загрузчике favicon

`is_public_host()` резолвит хост и отбрасывает loopback/private/link-local/reserved —
импорт чужого файла закладок больше не может сканировать локальную сеть и
`169.254.169.254`. Тип иконки определяется по сигнатуре файла (а не по заголовку
`Content-Type`), тело читается с жёстким лимитом, редиректы ограничены двумя,
SVG с `<script>`/`onload` не сохраняется.

## 9. Строгая Content-Security-Policy (без `unsafe-inline`)

Страница раньше держалась на инлайновых стилях, поэтому CSP была невозможна.
Теперь политика строгая — `default-src 'self'`, `script-src 'self'`, `style-src 'self'`,
`object-src 'none'`, `base-uri 'none'`, `form-action 'none'`, ни одного `unsafe-*`.

Чтобы это заработало, инлайновое убрано полностью:

| Было | Стало |
|---|---|
| `<style id="custom-css-style">` + `textContent = custom_css` | `<link href="/api/custom.css">`, cache-busting по хэшу содержимого |
| `<style id="dynamic-font-style">` (не использовался) | удалён |
| свои шрифты не подключались вообще | `/api/fonts/custom.css` генерирует `@font-face` для каждого файла в `static/fonts/Custom/` |
| 9 × `style="…"` в разметке | классы `.hidden-input`, `.mt-8`, `.mt-32`, `.hidden` |
| 8 × `style="…"` в JS-шаблонах | `data-bg="…"` + `applyDynamicColors()` (CSSOM — CSP его не блокирует) |

Фрейминг по умолчанию запрещён (`frame-ancestors 'none'` + `X-Frame-Options: DENY`).
Если страница встраивается (киоск, дашборд, превью) — `BOTYARA_FRAME_ANCESTORS="*"`
или список источников; тогда `X-Frame-Options` не отправляется.

Проверено в реальном headless Chromium: **0 нарушений CSP, 0 JS-ошибок**, при этом
темы, палитра акцентов, цветные плитки шорткатов, превью калькулятора и пользовательский
CSS применяются как раньше.

## 10. Иконки PWA

`manifest.json` ссылался на `/static/icon-192.png` и `icon-512.png`, которых не было
(404 при установке приложения). Иконки сгенерированы в стиле проекта (луна на тёмном
фоне, акцентный `#cba6f7`), добавлена maskable-версия для Android.

## 11. Прочее

- `websocket_sync` → `sync_enabled` с миграцией (значение пользователя сохраняется,
  миграция выполняется до вставки дефолтов);
- индексы на `search_history(searched_at)` и `shortcuts(group_name, position)`;
- загрузка шрифта проверяется по magic bytes (`wOF2`, `wOFF`, `OTTO`, `TrueType`), лимит 10 МБ;
- `LIKE`-поиск в автодополнении экранирует `%` и `_` (`ESCAPE '\'`);
- удаление активного фона сбрасывает `bg_image_id`/`bg_source`, а не оставляет битую ссылку;
- лимиты: 500 импортируемых шорткатов, 100 КБ заметка, 200 КБ значение настройки;
- неизвестные ключи настроек отбрасываются с отчётом `rejected`;
- Service Worker: `stale-while-revalidate` + версия кэша `v2` — правки CSS/JS теперь
  подхватываются без ручного бампа;
- CI: `pytest` без `||`-фолбэка (пустой прогон = красная сборка), плюс `compileall`
  и `node --check` для JS; добавлены `requirements-dev.txt`, `pytest.ini`.

## Что осталось осознанно

- **Авторизации нет** — это локальный инструмент, рубеж защиты — `HOST=127.0.0.1`
  по умолчанию плюс проверка Origin/Host. Если открывать наружу — нужен токен.
- **`custom_css`** исполняется как есть: это CSS самого пользователя, а не чужие данные.
- **`custom_css`** — единственный код, который пользователь пишет сам и который
  исполняется. Он отдаётся как обычная таблица стилей и может, например, скрыть
  элементы интерфейса. Это осознанная функция, а не дыра.
- **Фрейминг** по умолчанию запрещён; `BOTYARA_FRAME_ANCESTORS` ослабляет это
  намеренно (описано в README).
